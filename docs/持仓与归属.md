## 二、真正的约束不是“锁不锁”，是“卖不卖得动”

池子 USDT 侧只有 **8.079136 美元**。按现价，2.87 亿枚名义价值 $227.8，但只要真的卖出 1%（2,870,000 枚），池子会被瞬间击穿，价格趋近于零，实际到手远低于名义值。

结论：**这批持仓的经济意义在于“治理与划转凭证”，不在于变现能力。** 因此对外应该说“储备用途与划转规则”，而不是“锁仓”——链上并没有锁。

## 三、三个可选方案

| 方案 | 做法 | 成本 | 说服力 |

| A 只声明 | 官网/仓库写明用途，链上不动 | 0 | 弱：声明可随时推翻 |

**当前阶段建议 B**；等有 gas 预算再升级到 C。A 单独使用没有意义。

## 六、退出罚没的去向（penaltySink）

实测：

```
CINMiningVault            0x72DA093081377b679bF27A32Aaf091F9Ee7949E9
owner()                   0xb14c276ecd90158af14258cf62c8e1425a3f01af
penaltySink()             0xb14c276ecd90158af14258cf62c8e1425a3f01af   ← 指向运营钱包
setPenaltySink(address)   合约内存在该函数（选择器 0x1a20a1c5）
```

问题：提前退出的 30% 罚没现在打进运营钱包，等于“罚没归运营方”。改成社区钱包更符合文档里写的“罚没回到流动性池/社区”。

**改法**（owner 调用，gas ≈ 0.0000025 BNB，钱包余额够）：

```
合约：0x72DA093081377b679bF27A32Aaf091F9Ee7949E9
方法：setPenaltySink
参数：0xf64af315fd6f4c4dac6a51dd5fc728d927ecbf03
```

改完用 `penaltySink()` 复核应为 `0xf64a…bf03`。**这一步会改变罚没归属，属于资金流向变更，需运营方明确同意后执行。**
